# Lab: Exploring `cleanup.policy`, `retention.ms` and `segment.ms`

In this lab, you will see how Kafka's delete and compact cleanup policies work, and how segment rolling affects time-based retention. Use a disposable topic so the experiment cannot remove data from an application topic.

> The setting is named `cleanup.policy` (not `delete.policy`). Its supported policies are `delete`, `compact`, or both.

## Prerequisites

Run the commands from your Kafka installation directory, with the cluster listening on `localhost:9092`:

```bash
export BS=localhost:9092
```

## Step 1 — Create a disposable topic

```bash
bin/kafka-topics.sh \
  --bootstrap-server "$BS" \
  --create \
  --topic retention-lab \
  --partitions 1 \
  --replication-factor 1
```

Confirm that it exists:

```bash
bin/kafka-topics.sh \
  --bootstrap-server "$BS" \
  --describe \
  --topic retention-lab
```

## Step 2 — Explore time-based deletion

Set the topic to delete old data, retain it for one minute, and roll segments every ten seconds:

```bash
bin/kafka-configs.sh \
  --bootstrap-server "$BS" \
  --entity-type topics \
  --entity-name retention-lab \
  --alter \
  --add-config cleanup.policy=delete,retention.ms=60000,segment.ms=10000
```

Inspect the topic-level overrides:

```bash
bin/kafka-configs.sh \
  --bootstrap-server "$BS" \
  --entity-type topics \
  --entity-name retention-lab \
  --describe
```

Produce an initial batch of records:

```bash
bin/kafka-console-producer.sh \
  --bootstrap-server "$BS" \
  --topic retention-lab
```

Enter a few lines, for example:

```text
first batch - record 1
first batch - record 2
```

Wait at least 10 seconds, then produce another batch to give Kafka an opportunity to roll the active segment:

```bash
bin/kafka-console-producer.sh \
  --bootstrap-server "$BS" \
  --topic retention-lab
```

Enter:

```text
second batch - record 1
second batch - record 2
```

Read the records from the beginning:

```bash
bin/kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic retention-lab \
  --from-beginning
```

Wait at least 60 seconds plus the broker's `log.retention.check.interval.ms`, then run the consumer again to observe which records remain. That broker setting is commonly several minutes, so cleanup may take several minutes after the retention threshold. Kafka deletes eligible **closed segments**, not individual records exactly 60 seconds after they were produced. `segment.ms` controls segment rolling; it is not itself a retention duration. For predictable rolling in this exercise, append records after the segment interval has elapsed.

## Step 3 — Explore compaction by key

Switch the topic to compaction:

```bash
bin/kafka-configs.sh \
  --bootstrap-server "$BS" \
  --entity-type topics \
  --entity-name retention-lab \
  --alter \
  --add-config cleanup.policy=compact
```

Produce keyed values. Use `key:value` lines:

```bash
bin/kafka-console-producer.sh \
  --bootstrap-server "$BS" \
  --topic retention-lab \
  --property parse.key=true \
  --property key.separator=:
```

Enter several values for the same key and for another key:

```text
order-1:created
order-2:created
order-1:paid
order-1:shipped
```

Wait at least 10 seconds, then append one more record to give Kafka an opportunity to roll the segment containing the keyed records:

```text
order-3:pending
```

Read the records and display their keys:

```bash
bin/kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic retention-lab \
  --from-beginning \
  --property print.key=true \
  --property key.separator=:
```

You may initially see every value. Compaction happens asynchronously on eligible closed segments and retains the latest value for each key eventually; it does not immediately replace old records or guarantee that a consumer will only ever see one record per key.

## Step 4 — Explore using both policies

Set both policies:

```bash
bin/kafka-configs.sh \
  --bootstrap-server "$BS" \
  --entity-type topics \
  --entity-name retention-lab \
  --alter \
  --add-config "cleanup.policy=[compact,delete]"
```

Verify the configuration:

```bash
bin/kafka-configs.sh \
  --bootstrap-server "$BS" \
  --entity-type topics \
  --entity-name retention-lab \
  --describe
```

With both policies enabled, Kafka can compact records by key and also remove old segments according to retention. Time-based deletion still works at the segment level.

## Step 5 — Clean up

The topic is disposable. Delete it when you have finished:

```bash
bin/kafka-topics.sh \
  --bootstrap-server "$BS" \
  --delete \
  --topic retention-lab
```

## Key takeaways

- Use `cleanup.policy=delete` for time- or size-based removal of old segments.
- Use `retention.ms` to configure the time retention threshold; cleanup is asynchronous and segment-based.
- Use `segment.ms` to control the time-based segment rolling threshold, not the retention period.
- Use `cleanup.policy=compact` to retain the latest value for each key eventually.
- Use `cleanup.policy=[compact,delete]` to enable both compaction and deletion.
